## What the numbers mean

- **Stars** — `stargazerCount` from the GitHub API.
- **Downloads** — cumulative downloads of all release assets across all published releases (not repository clones or package downloads).
- **Open issues** — open issues only; pull requests are excluded.
- **Latest tag** — the tag ref with the most recent commit date, or `—` when a repository has no tags.
- **Updated** — date of the repository's last push/update.

Repositories are sorted by stars, then downloads, then name. Archived repositories and forks are labelled.

## Automatic updates

[`.github/workflows/update-readme.yml`](.github/workflows/update-readme.yml) runs on a daily schedule and on demand (Actions → **Update monitor** → **Run workflow**). It regenerates the block between the monitor markers and commits the result when anything changed. The raw snapshot used to build the table is stored in [`data/projects.json`](data/projects.json).

## Run it locally

Requires Python 3.9+ and either a `GITHUB_TOKEN`/`GH_TOKEN` environment variable or an authenticated GitHub CLI session (`gh auth login`).

```powershell
python scripts/update_readme.py
```

To monitor a different account:

```powershell
$env:GITHUB_USER = "another-user"
python scripts/update_readme.py
```

Edits outside the `START MONITOR` / `END MONITOR` markers are preserved on every refresh.
